# Convention

이 스킬은 이 저장소의 Git 협업 규칙을 적용할 때 사용한다.

## 사용 시점

- 커밋 메시지를 작성하거나 제안할 때
- 브랜치 전략이나 브랜치 이름을 정할 때
- PR 제목이나 본문을 작성할 때
- merge 방식이나 협업 규칙을 확인할 때

## 작업 절차

1. 먼저 [docs/commit-convention/README.md](../../../docs/commit-convention/README.md)를 읽는다.
2. 커밋 메시지, 브랜치, PR 제목과 본문, merge 방식은 해당 문서의 규칙을 그대로 따른다.
3. 요청이 모호하면 문서 기준으로 가장 보수적인 해석을 우선한다.

## 핵심 규칙

- 커밋/PR 제목 형식은 `<type>: <한국어 설명>`을 사용한다.
- 제목에는 스코프를 넣지 않는다.
- `main`, `dev`에는 직접 push하지 않고 PR로만 머지한다.
- 로컬에서 직접 `git merge`로 `main`, `dev`를 머지하지 않는다.
- 팀이 익숙해질 때까지 `rebase`는 사용하지 않는다.

## 출력 규칙

- 커밋 메시지 제안은 바로 복사 가능한 텍스트 블록으로 반환한다.
- PR 설명은 변경 내용, 이유, 테스트, 체크리스트 중심으로 작성한다.
- 문서와 충돌하는 관행이 보이면 이 스킬의 기준 문서를 우선 적용한다고 명시한다.

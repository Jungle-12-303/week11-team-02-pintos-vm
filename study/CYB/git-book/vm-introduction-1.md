# VM Introduction 1 번역

## Project3: Virtual Memory

이제 여러분은 Pintos의 내부 동작에 어느 정도 익숙해졌을 것이다. 여러분의 운영체제는 적절한 동기화를 바탕으로 여러 실행 흐름을 올바르게 처리할 수 있고, 여러 사용자 프로그램도 동시에 적재할 수 있다. 하지만 실행할 수 있는 프로그램의 개수와 크기는 머신의 주기억장치 크기에 의해 제한된다. 이번 과제에서는 무한한 메모리가 있는 것처럼 보이게 만드는 환상을 구축하여 그 제한을 제거한다.

이번 과제는 이전 프로젝트 위에 이어서 구현한다. project 2의 테스트 프로그램들은 project 3에서도 계속 동작해야 한다. 따라서 project 3을 시작하기 전에 project 2 제출물에 남아 있는 버그를 먼저 고쳐 두는 것이 중요하다. 그런 버그들은 project 3에서도 거의 그대로 같은 문제를 일으킬 가능성이 크다.

project 3에서는 이해를 돕기 위해 단계별 지침을 제공한다.

## Background

### Source Files

이번 프로젝트에서는 `vm` 디렉터리에서 작업하게 된다. `Makefile`은 `-DVM` 설정이 켜지도록 이미 갱신되어 있다. 우리는 매우 많은 양의 템플릿 코드를 제공한다. 반드시 제공된 템플릿을 따라야 한다. 즉, 제공된 템플릿을 기반으로 하지 않은 코드를 제출하면 0점을 받는다. 또한 `"DO NOT CHANGE"`라고 표시된 템플릿은 절대 수정해서는 안 된다. 아래에서는 여러분이 수정하게 될 각 템플릿 파일의 역할을 간단히 설명한다.

#### `include/vm/vm.h`, `vm/vm.c`

가상 메모리를 위한 일반 인터페이스를 제공한다. 헤더 파일에는 `vm_type`의 정의와 설명이 있다. 여러분의 가상 메모리 시스템은 `VM_UNINIT`, `VM_ANON`, `VM_FILE`, `VM_PAGE_CACHE`를 지원해야 한다. 지금은 `VM_PAGE_CACHE`는 무시해도 되며, 이것은 project 4에서 사용된다. 또한 여기에서 supplementary page table도 구현하게 된다.

#### `include/vm/uninit.h`, `vm/uninit.c`

초기화되지 않은 페이지(`vm_type = VM_UNINIT`)를 위한 연산을 제공한다. 현재 설계에서는 모든 페이지가 처음에는 uninitialized page로 설정되고, 이후 anonymous page나 file-backed page로 변환된다.

#### `include/vm/anon.h`, `vm/anon.c`

anonymous page(`vm_type = VM_ANON`)를 위한 연산을 제공한다.

#### `include/vm/file.h`, `vm/file.c`

file-backed page(`vm_type = VM_FILE`)를 위한 연산을 제공한다.

#### `include/vm/inspect.h`, `vm/inspect.c`

채점을 위한 메모리 검사 연산을 포함한다. 이 파일들은 수정하지 마라.

이번 프로젝트에서 작성하는 코드의 대부분은 `vm` 디렉터리와 이전 프로젝트에서 다루었던 파일들에 들어가게 된다. 다만 다음과 같은 몇몇 파일은 이번에 처음 접할 수 있다.

#### `include/devices/block.h`, `devices/block.c`

블록 장치에 대해 섹터 단위의 읽기/쓰기 접근을 제공한다. 여러분은 이 인터페이스를 사용해 swap partition을 블록 장치처럼 다루게 된다.

## Memory Terminology

이제 메모리와 저장장치에 관한 몇 가지 용어를 정리한다. 이 중 일부는 project 2의 Virtual Memory Layout에서 이미 본 적이 있을 수 있지만, 많은 내용은 새롭다.

## Pages

페이지(page), 또는 virtual page는 크기 4,096바이트(한 페이지 크기)의 연속된 가상 메모리 구간이다. 페이지는 반드시 페이지 정렬(page-aligned)되어야 하며, 즉 시작 주소가 페이지 크기로 정확히 나누어떨어져야 한다. 따라서 64비트 가상 주소의 마지막 12비트는 page offset(또는 그냥 offset)이다. 그 상위 비트들은 나중에 소개할 페이지 테이블에서의 인덱스를 나타내는 데 사용된다. 64비트 시스템에서는 4단계 페이지 테이블을 사용하므로, 가상 주소는 다음과 같은 모양이 된다.

```text
63          48 47            39 38            30 29            21 20         12 11         0
+-------------+----------------+----------------+----------------+-------------+------------+
| Sign Extend |    Page-Map    | Page-Directory | Page-directory |  Page-Table |    Page    |
|             | Level-4 Offset |    Pointer     |     Offset     |   Offset    |   Offset   |
+-------------+----------------+----------------+----------------+-------------+------------+
              |                |                |                |             |            |
              +------- 9 ------+------- 9 ------+------- 9 ------+----- 9 -----+---- 12 ----+
                                          Virtual Address
```

각 프로세스는 독립적인 사용자(가상) 페이지 집합을 가진다. 이는 `KERN_BASE (0x8004000000)` 아래에 있는 페이지들이다. 반면 커널(가상) 페이지 집합은 전역적이며, 어떤 스레드나 프로세스가 실행 중이든 항상 같은 위치에 존재한다. 커널은 사용자 페이지와 커널 페이지 모두에 접근할 수 있지만, 사용자 프로세스는 자기 자신의 사용자 페이지에만 접근할 수 있다. 자세한 내용은 Virtual Memory Layout을 참고하라.

Pintos는 가상 주소를 다루기 위한 여러 유용한 함수를 제공한다. 자세한 내용은 Virtual Addresses 절을 보라.

## Frames

프레임(frame), 또는 physical frame, page frame은 연속된 물리 메모리 구간이다. 페이지와 마찬가지로 프레임도 페이지 크기 단위이고 페이지 정렬되어 있어야 한다. 따라서 64비트 물리 주소 역시 frame number와 frame offset(또는 그냥 offset)으로 나눌 수 있다.

```text
                          12 11         0
    +-----------------------+-----------+
    |      Frame Number     |   Offset  |
    +-----------------------+-----------+
              Physical Address
```

x86-64는 물리 주소의 메모리에 직접 접근하는 방법을 제공하지 않는다. Pintos는 이를 우회하기 위해 커널 가상 메모리를 물리 메모리에 직접 매핑한다. 즉, 커널 가상 메모리의 첫 번째 페이지는 물리 메모리의 첫 번째 프레임에, 두 번째 페이지는 두 번째 프레임에, 이런 식으로 대응된다. 따라서 프레임은 커널 가상 메모리를 통해 접근할 수 있다.

Pintos는 물리 주소와 커널 가상 주소 사이를 변환하는 함수도 제공한다. 자세한 내용은 Virtual Addresses를 참고하라.

## Page Tables

페이지 테이블(page table)은 CPU가 가상 주소를 물리 주소로 변환하는 데 사용하는 자료구조다. 즉, 페이지를 프레임으로 변환한다. 페이지 테이블의 형식은 x86-64 아키텍처에 의해 결정된다. Pintos는 `threads/mmu.c`에서 페이지 테이블 관리 코드를 제공한다.

아래 그림은 페이지와 프레임의 관계를 보여 준다. 왼쪽의 가상 주소는 page number와 offset으로 구성된다. 페이지 테이블은 page number를 frame number로 변환하고, 변하지 않은 offset과 결합하여 오른쪽의 물리 주소를 얻는다.

```text
                          +----------+
         .--------------->|Page Table|-----------.
        /                 +----------+            |
        |   12 11 0                               V  12 11 0
    +---------+----+                         +---------+----+
    | Page Nr | Ofs|                         |Frame Nr | Ofs|
    +---------+----+                         +---------+----+
     Virt Addr   |                            Phys Addr    ^
                  \\_______________________________________/
```

## Swap Slots

swap slot은 swap partition 안의 페이지 크기 디스크 공간 구간이다. 슬롯의 배치에 대한 하드웨어 제약은 프레임보다 덜 엄격하지만, 페이지 정렬로 두는 데 단점이 없으므로 swap slot도 페이지 정렬하는 것이 좋다.
